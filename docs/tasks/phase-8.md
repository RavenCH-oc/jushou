# Phase 8：搶答，以及計時器「時間到」改成畫面提示

先讀 `CLAUDE.md`、`docs/PRODUCT.md`、`status.md`。Phase 6 已合併並部署。Phase 7（Word 匯入）暫緩，所以這一輪直接做 Phase 8。

## 為什麼做

1. **搶答**：老師口頭問一題，學生手機上按大按鈕「搶！」，投影排出誰最先按。上課很常用，也是第一個需要「全班同時按」的功能
2. **計時器**：在教室試用後，時間到的嗶聲太尖。改成**不出聲**，跳出一個大的「時間到」提示，老師按一下關掉

## 1. 計時器：時間到改成大提示（先做，很小）

- 拿掉 `beep()` 和所有 Web Audio 程式碼，**完全不出聲**
- 時間到時，畫面中央跳出提示：大字「**時間到**」（至少 96px，投影從教室後面看得到），一顆主要按鈕「**知道了**」
- 提示蓋住上課畫面中間的大部分區域（半透明深色背景＋白色卡片就好，不要動畫）。不會自己消失
- 按「知道了」或按 Esc 會關閉提示**和**右上角的計時器
- 右上角的計時器在時間到後照舊變色，顯示「時間到」，作為提示關掉前的備援
- 老師端別的畫面元件（例如臨時出題的 Modal）開著的時候時間到：提示照樣出現在最上層
- 更新 `status.md`，刪掉「嗶聲」那一條已知問題

## 2. 搶答

### 老師操作

- 上課畫面的工具按鈕加「**搶答**」，放在「臨時出題」「抽人」「計時器」那一群。在 1366×768 仍然不能換行
- 按下後直接開始一輪（不用再按一次確認），開一個佔滿上課畫面的搶答畫面（用現有 `Modal` 或同等的全畫面區塊）：
  1. **倒數**：大字「3 → 2 → 1」，然後顯示「**搶！**」
  2. **排名**：最先按的人最大：「第 1 名　12 號 王小明」，第 2、3 名小一號，第 4、5 名再小一號；超過 5 人只顯示「還有 N 人也按了」
  3. 下方一行：「已加入 28 人，已經有 7 人按了」
- 按鈕：
  - 主要按鈕「**結束搶答**」：結束這一輪，關閉搶答畫面
  - 次要按鈕「**再搶一次**」：清掉排名，馬上開始新一輪（重新倒數）
- 開始搶答時如果有題目在作答中，就跟「臨時出題」一樣自動停止作答；正在互評中則沿用現有的「結束互評？」確認
- 沒有任何學生加入時，「搶答」按鈕照樣可以按，畫面寫「還沒有學生加入」

### 學生操作

- 一輪開始後，手機畫面（蓋過原本的題目或等待畫面）顯示：
  - 倒數中：大字「3、2、1」，按鈕灰色、按了沒反應
  - 倒數結束：一顆**很大的按鈕「搶！」**（至少佔螢幕寬度、高度 160px 以上），整顆可點
  - 按下後：「**你是第 3 個按的**」。不顯示別人的名字
- 老師按「結束搶答」：手機回到原本的畫面（題目、結果或等待畫面）。正在作答但還沒送出的內容**不能消失**（搶答畫面要蓋在上面，不要卸載題目元件；或用其他方式保留草稿）
- 老師按「再搶一次」：手機重新倒數

### 公平性：倒數由伺服器決定

各手機收到「開始了」的時間會差到零點幾秒，所以要用倒數抵銷：

- 開始一輪時，伺服器記下「**幾點幾分幾秒開放按**」＝現在 + 3 秒
- 學生的 state 回傳「**還有幾毫秒開放**」（由伺服器算好，不要傳時間點，避免手機時鐘不準），手機用收到回應的那一刻加上這個數字，算出何時亮起按鈕
- 伺服器收到「搶」時：
  - 還沒到開放時間 → 拒絕，回「還沒開始，等倒數結束再按。」（正常操作不會發生）
  - 這一輪已結束 → 回「這一輪搶答已經結束了。」
  - 同一個人重複按 → 回傳他原本的名次，不重複記錄
- **名次用伺服器收到的順序**，不要用手機送來的時間。存一個遞增的序號，不要用時間戳記排序，避免同時間並列

### 資料

- 新 migration `0009`，欄位自己設計，需要存：目前這一輪（沒有就是空）、這一輪的狀態、開放時間，以及這一輪誰按了、先後順序
- **不需要保留歷史**：開始新一輪時，可以刪掉上一輪的紀錄。結束上課時一併清掉
- 搶答**不進**上課紀錄、成績、Excel，也不算出席

### 即時連線與請求數（重要）

Cloudflare 免費方案每分鐘最多 1,000 次請求。如果每有一人按，就通知全班重抓，30 人按完會產生約 900 次請求，所以：

- 新增事件 `"buzz"`
- 開始一輪、再搶一次、結束搶答：通知**全班**（`to: "all"`）
- 學生按「搶」：只通知**老師**（`to: "teacher"`）。學生自己的名次直接放在「搶」這個 API 的回應裡，其他學生**不收任何通知**
- 老師端收到 `"buzz"` 時，**不要重抓整個上課資料**（`GET /lessons/:id` 很重），改抓一個輕量的搶答 API，只回排名和人數
- 老師端短時間收到很多個 `"buzz"` 時要合併：正在抓的時候又收到，就等這次抓完再抓一次，不要同時發很多個請求
- 估算：一輪約「開始 30 + 按 30 + 老師最多 30 + 結束 30」≈ 120 次請求，一分鐘搶好幾輪也在上限內。請在 PR 說明寫出你實際的估算

### 安全

- 開始、再搶一次、結束、看排名都是老師 API，未登入回 401
- 「搶」只接受**已綁定座號、而且這堂課正在上**的學生；加入碼錯誤或沒綁定回白話錯誤
- 學生端拿不到別人的名字和名次

## 驗收

- `pnpm typecheck`、`pnpm test`、`pnpm build` 通過
- 測試至少涵蓋：
  - 名次照伺服器收到的順序；重複按回傳同一個名次
  - 倒數還沒結束時按會被拒絕（倒數長度做成可以在測試裡替換的常數，或用 fake timers）
  - 結束後按會被拒絕；「再搶一次」清空排名
  - 開始搶答會停止正在作答的題目
  - 學生按「搶」只通知老師；開始和結束才通知全班（用 `src/worker/test/hub.ts` 檢查）
  - 學生 state 不含別人的名字或名次
  - 老師 API 未登入回 401；沒綁定的手機不能搶
  - 結束上課後搶答資料被清掉，紀錄和分數不受影響
- 手動測試：本機 1 個老師分頁 + 3 個學生視窗，連續搶 3 輪，其中一輪是在題目作答中開始的；確認搶答結束後，學生的作答草稿還在
- PR 附截圖：老師端倒數、老師端排名（至少 4 人）、學生端倒數、學生端「搶！」按鈕、學生端「你是第 N 個按的」、計時器「時間到」提示
- PR 描述用老師和學生的角度各寫一段流程，附 `pnpm build` 的檔案大小和請求數估算
- 更新 `docs/PRODUCT.md`（上課小工具一節加搶答、計時器改成畫面提示）和 `status.md`

## 不要做

- 以組為單位搶答、搶答加分、搶答紀錄存進資料庫的歷史或 Excel
- 搶到的人自動跳出作答框、或自動接到抽人
- 搶答音效（任何聲音都不要）
- 介面整理（下一個階段老師端、學生端一起做）
- Word 匯入、題目圖片
- 部署（使用者 merge 後自己決定）
