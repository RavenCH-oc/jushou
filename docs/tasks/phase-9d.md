# Phase 9d：視覺整理（四）學生端

先讀 `CLAUDE.md`（「介面原則」的學生端規則、「樣式規則」）、`docs/tasks/phase-9c.md`。9a～9c 都已合併部署；使用者用投影機試過上課畫面，沒問題。

## 為什麼做

學生端在 9a 只換了顏色，排列還是舊的：沒有頂部列（只有一行灰色小字「2 號 李大華」）、題目直接放在灰藍背景上、選座號和下課結果是一格一格 2px 粗框、搶答按鈕的白字是寫死的。這是 Phase 9 的最後一輪，做完學生端和老師端就是同一套樣子。

**只改外觀和排列，不改功能**。例外只有第 6 節「互評評語框加上字數上限」，這是一個小的輸入限制。

學生用手機直式為主，很多是舊手機：

- 按鈕至少 48px 高（`--tap`），選項整列可點（現在就是這樣，不能退步）
- 字級**不准變小**
- 不加動畫、不加 `position: sticky`、不加大圖或陰影堆疊（舊手機捲動會卡）
- 學生端 JS 要維持在預算內（現在約 5.5 KB＋題目元件，遠低於 80 KB）

## 1. 學生頂部列

- 細的深色列（`--appbar` 底、白字），高度約 48px，整個寬度，放在 `.page` 外面。**不要 sticky**
- 左邊：班級名（白字、粗體）；還沒加入（輸入加入碼的畫面）時寫「舉手」
- 右邊：選好座號後顯示「2 號 李大華」（`--appbar-muted` 色，名字太長截斷加「…」）；還沒選座號時不顯示
- 刪掉原本內容上方那行 `.who`（「2 號 李大華」灰色小字）
- 頂部列沒有任何按鈕或連結（學生不需要導覽）
- 「請不要關閉這個分頁」的提醒（`.notice`）維持在頂部列下面、內容上面
- 搶答畫面蓋上來的時候，頂部列維持顯示（讓學生知道自己是誰）

## 2. 每個畫面放進一張白卡片

學生端每個狀態的主要內容放進一張 `.card`（白底、1px 框、淡陰影），跟老師端的「舞台卡片」同一個概念。手機上卡片左右留 12px 邊距、卡片內 padding 16px（不要太大，360px 寬的手機要放得下）。

| 畫面 | 怎麼排 |
| --- | --- |
| 輸入加入碼 | 卡片置中：「輸入老師給的加入碼」、大的數字輸入框、「加入」主要按鈕 |
| 老師還沒開始上課／這堂課結束了 | 卡片置中：灰字班級名、大字狀態、說明；「換一個加入碼」次要按鈕在卡片裡最下面 |
| 選座號 | 見第 3 節 |
| 等老師出題 | 卡片置中：「2 號 李大華，已加入」大字、「等老師出題」、「不是我？」文字按鈕 |
| 作答中 | 見第 4 節 |
| 老師停止作答 | 卡片：題目（鎖住的選項）＋狀態說明 |
| 公布答案 | 見第 5 節 |
| 互評 | 見第 6 節 |
| 下課結果 | 見第 7 節 |

載入中、連不上伺服器的畫面也放卡片。

## 3. 選座號

- 一張卡片，標題「{班級名}」、說明「請點你的座號和名字」
- 座號清單改成 9b 的列表樣式：每個座號一列，1px 分隔線，**不再一格一格 2px 粗框**
  - 每列至少 56px 高、整列可點；左邊座號（大字粗體、固定寬度對齊），右邊名字
  - 已有人使用：整列 `--text-muted` 字、`--surface-soft` 底，右邊小標籤 `.badge-neutral`「已有人使用」。點了照現在的行為顯示錯誤訊息（錯誤訊息在那一列下面）
  - 按下去的瞬間（`:active`）底色 `--primary-soft`，讓學生知道有點到

## 4. 作答中

- 題目（題號・題型・分數、題目文字、出處備註、選項或輸入框）整塊放進卡片
- **選項框**（`question-view.css`）：2px 改 1px `--border-strong`；選中時框線主色、底色 `--primary-soft`，**選中前後版面不能跳動**（現在用 `box-shadow: inset` 補粗細，維持這個做法）
- 選項的字母圓圈：2px 改 1px `--border-strong`；選中維持主色填滿
- 是非題的大按鈕、臨時題的「只有字母」選項維持現在的大小
- 卡片下面（卡片外）：
  - 已送出：`--success-soft` 底的提示框（1px `--success` 框、`--success` 字）「✓ 已送出，可以在老師停止前修改」
  - 改過還沒再送：維持 `.notice`（warning）「答案改了，記得再按一次『送出答案』。」
  - 「送出答案」主要按鈕，維持 64px 高、24px 字、整列寬；停用時維持 9a 的灰色填滿
- **注意**：`question-view.css` 也用在老師上課畫面和題組預覽。改完要看老師上課畫面（作答中）截圖，確認投影上的選項框還清楚，沒有變淡到看不見

## 5. 公布答案

- 結果大框（「○ 答對了」「✕ 答錯了」…）：3px 改 2px，其他（顏色、大字）維持
- 「得 N／M 分」、題號、題目、選項結果放進卡片
- 選項結果列（`.reveal-options`）、填空結果（`.reveal-blanks`）：2px 改 1px `--border`；正確答案那列維持 `--success-soft` 底＋`--success` 框
- 「你選的」標籤改成小標籤 `.badge-neutral`；「✓ 正確答案」維持 `--success` 粗體字
- 簡答「你的回答」框：`--surface-soft` 底、不要框線（現在就是，確認）

## 6. 互評

- 卡片：標題「請評這位同學的答案」、題目、同學答案框、給分、評語、送出
- 同學答案框：`--surface-soft` 底、1px `--border`（2px 改 1px）；`max-height: 45vh` 捲動維持
- 1～5 分按鈕：1px `--border-strong`；選中維持主色填滿；維持 56px 高、26px 字
- **評語框加 `maxLength={REVIEW_MAX_LENGTH}`**：用 `src/shared/peer-review.ts` 已經有的常數（200），跟伺服器檢查同一個數字，不要另外寫死。加了之後打不進第 201 個字，「還可以寫 N 字」照樣顯示；剩 20 字以內時字改 `--warning` 色。原本「超過 N 字，請刪短一點」的錯誤狀態保留（貼上很長的文字時瀏覽器會截斷，理論上不會出現，但留著無害）
- 送出後、老師結束互評前的畫面，以及「同學給你的評語」（`.review-received`）：`--primary-soft` 底、1px `--primary` 框（2px 改 1px）

## 7. 下課結果

- 一張卡片：「這堂課結束了，謝謝！」、題組名、總分（大字）
- 每題結果改成 9b 的列表樣式（一列一題、1px 分隔線），不再一格一格 2px 粗框：
  - 左邊「1. 題目開頭」，太長截斷
  - 右邊結果：答對 `--success` 粗體、答錯 `--danger` 粗體、其他 `--text-muted`；分數照現在的寫法
  - 拿掉答對／答錯整列的彩色底色（列表裡整列染色太花），只留右邊結果文字的顏色
- 「簡答題老師批改後另外計分」「老師開始下一堂課時…」說明、「換一個加入碼」次要按鈕，放在卡片裡最下面

## 8. 搶答

- 搶答畫面維持蓋住作答畫面（不卸載，草稿要還在——這是 Phase 8 的規則，不能動）
- 「搶！」按鈕：寫死的 `#fff` 換成 `--primary-text`；底色維持 `--danger`、大小維持（200px 高、64px 字）
- 還不能按（倒數中）的按鈕：底色 `--disabled`、字 `--disabled-text`（現在是灰底白字，看不太清楚）
- 按下去後的「你是第 N 名」：維持大字主色
- 倒數數字維持 120px 主色
- 整塊放進卡片，標題「搶答」維持

## 驗收

- `pnpm typecheck`、`pnpm test`、`pnpm build` 通過；PR 附 build 大小（學生端 JS 應該幾乎不變）
- 不新增 npm 依賴；不用圖示
- `grep` 檢查：`student.css`、`question-view.css` 沒有寫死色碼（`#fff` 等）、沒有 `border: 2px`／`3px`（是非題、結果大框等規格允許的除外，列在 PR 說明）
- **PR 附改前／改後截圖，手機寬 375×812**（同一個畫面並排）：
  - 輸入加入碼、老師還沒開始、選座號（有一兩個「已有人使用」）、等老師出題
  - 作答中：單選（已送出）、是非題、填空、簡答
  - 公布答案：答錯（單選）、簡答
  - 互評（評語打到剩不到 20 字）、收到評語
  - 搶答：倒數中、可以按、名次
  - 下課結果（有答對、答錯、沒作答、待批改）
- 360 寬再補一張「作答中（單選）」和「選座號」，確認最小的手機放得下
- **老師上課畫面（作答中）1366×768 一張**，確認 `question-view.css` 改了之後投影上的選項框還清楚
- 手動確認流程沒變：加入 → 選座號 → 作答送出 → 改答案再送 → 老師停止 → 公布；互評送出；搶答時草稿還在、結束後能送出；下課結果
- 如果方便，用一支真手機（舊一點的更好）走一遍，PR 附一張手機截圖

## 不要做

- 改 API、即時更新、搶答規則、互評規則
- 學生端加任何導覽或新功能
- 動老師端（除了 `question-view.css` 的連帶影響要確認）
- 動畫、`sticky`、圖示、深色模式
- 部署
