# Phase 3.5：真機試用後的介面修正

先讀 `CLAUDE.md`、`status.md`。Phase 3 已合併並部署。

使用者用兩支 4G 手機跑完一堂課，即時更新都正常。老師（使用者的媽媽）實際操作後，回報了下面這些卡點。這一輪**只改介面和操作流程**，不加新功能、不改資料表（第 7 點除外，它只讀現有資料）。

## 1. 老師端在 16:9 橫向螢幕要用滿畫面（最重要）

學校電腦和投影機都是 1920×1080、1366×768 這類橫向螢幕。目前老師端內容最寬只有 960～1200px，在大螢幕上兩邊空一大塊，字也偏小，要手動縮放才看得清楚。

- **上課畫面**（會投影）：不設最大寬度，用滿整個視窗（左右留 2～3% 邊距）。字級改用 `clamp()` 跟著視窗寬度變大，例如題目 `clamp(32px, 3.2vw, 64px)`、選項 `clamp(22px, 2vw, 40px)`、「已作答 N／M 人」的數字 `clamp(40px, 4vw, 80px)`、加入碼 `clamp(96px, 12vw, 240px)`。目標：1366×768 和 1920×1080 都不用縮放、不用捲動，就能看清楚一題（4 個選項以內）
- 左側題目列表在寬螢幕維持左右兩欄，但列表欄固定在約 20% 寬，題目區佔其餘
- 上課畫面加一個「全螢幕」次要按鈕（`requestFullscreen`，再按一次離開）
- **其他老師頁面**（首頁、班級、題組、題目編輯）：最大寬度放寬到約 1400px，內文字級維持 20px 即可，不用跟著放大
- 用 Playwright 在 1366×768 和 1920×1080 各截一張上課畫面（作答中、4 個選項的單選題），附在 PR

## 2. QR code 要能從教室後面掃

- 大小跟著視窗：在等待加入畫面約佔視窗高度的 45%（`min(45vh, 30vw)`）。投影機解析度低，要大才掃得到
- 模組周圍留足白邊（至少 4 個模組寬），用純黑白
- QR 內容改成 `網址/?code=加入碼`。學生端打開時，如果網址帶 `code`，就跳過輸入加入碼，直接到選座號（或已綁定時直接進課堂），然後用 `history.replaceState` 把 `?code=` 從網址拿掉
- 網址列印在 QR 下方，也照第 1 點用 `clamp()` 放大

## 3. 「下一題」直接推送

老師希望按「下一題」就直接開始作答，不要再多按一次「出這一題」。

- 目前題目「已公布」後，主要按鈕是「出下一題」：按下直接把下一題設為作答中並推送給學生（後端已經支援開新題時自動停止舊題）
- 在左側列表點其他題目時，維持現在的行為：只切換老師畫面，按「出這一題」才推送（老師想跳題、回頭重出時用）
- 最後一題公布後，主要按鈕維持「結束上課」

## 4. 「新增題目」不好找

題組頁的「新增題目」按鈕在右上角，離題目列表太遠，老師找了一下才看到。

- 在題目列表**最下面**放一個整列寬的大按鈕「＋ 新增第 N 題」（N = 題數 + 1），新題目會出現在這個位置，視線自然往下找得到
- 題組是空的時，列表位置直接顯示這個按鈕和一句「這個題組還沒有題目」
- 右上角的「新增題目」可以拿掉，避免同一個動作有兩個入口

## 5. 選項空白時的錯誤訊息

選項沒填時，目前只說「選項 D 還沒有內容。」，老師不知道可以刪掉。改成：

> 選項 D 還沒有內容。不需要這個選項的話，可以按下面的「刪除」。

選項只剩 2 個時不能刪，訊息就只說「選項 D 還沒有內容。」

## 6. 「← 回首頁」等返回連結太小

所有「← 回…」連結改成較大的點擊範圍：字級 20px、高度至少 48px、可以做成次要按鈕的樣式（細框）。位置不變。

## 7. 學生下課時看得到自己每題的結果

手機螢幕關掉再打開時，學生會直接看到下一題，看不到上一題的對錯。與其處理各種錯過的情況，不如在下課畫面統一補上：

- 「這堂課結束了，謝謝！」下面列出這堂課每一題：題號、題目前 20 字、自己的結果（答對／答錯／沒作答／老師之後批改），以及總分
- 只顯示**已公布**的題目的結果；沒公布的題目顯示「老師沒有公布答案」
- 學生 API 回傳這份清單時，同樣只能是這位學生自己的資料
- 下課後才打開頁面的學生，目前看到的是「老師還沒開始上課」。改成：如果這支手機在**今天**有參加過已結束的課，顯示那堂課的結果（今天以 Asia/Taipei 計）；之後老師開新課時照常自動進入

## 8. 上課中不能重新產生加入碼

上課中重新產生加入碼，所有學生會被踢出。上課中把班級設定裡的「重新產生加入碼」按鈕停用，旁邊說明「上課中不能更換，下課後再換」。後端也要擋（409）。

## 關於手機方向鎖

不需要做。網頁的方向鎖只有在全螢幕的 Android 上能用，iOS 不支援，而且學生端沒有需要橫向的功能。只要確認學生端在手機**橫放**時版面不會壞掉（可以捲動、按鈕按得到）即可。

- 新增測試：`?code=` 的處理、上課中重新產生加入碼回 409、下課結果清單只含自己的資料且未公布的題目不含答案
- PR 附截圖：上課畫面（1366×768、1920×1080 各一）、等待加入畫面（1920×1080）、題組頁、學生下課結果畫面（手機）
