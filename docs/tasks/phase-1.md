# Phase 1：班級、學生名冊、分組

先讀 `CLAUDE.md`、`docs/PRODUCT.md`、`status.md`。Phase 0 已合併到 main。

## 目標

老師可以建立班級、貼上學生名冊、做出分組並投影給全班看。這個階段只有老師端，學生端不變。

## 資料表（新 migration）

依需求自行設計，原則：
- 班級：名稱、加入碼（6 位數字，不重複，可重新產生）、建立時間
- 學生：所屬班級、座號、姓名。同班座號不可重複
- 分組：一個班級可有多套分組（名稱，例如「第一次報告分組」）；每套有多個組（組名、順序）；每位學生在同一套分組裡最多屬於一組
- 刪除班級要連帶刪除學生和分組（之後也會連帶刪除上課紀錄，畫面上要講清楚）
- ID 用 `crypto.randomUUID()`，時間用 ISO 字串即可

不需要做版本紀錄、草稿狀態、快照。

## 老師端畫面

### 首頁
- 班級列表（卡片或列表，顯示班名、人數）
- 主要按鈕：「新增班級」

### 新增／編輯班級
- 只要填班級名稱
- 加入碼自動產生，顯示在班級頁

### 班級頁
分三塊，用簡單的分頁（tab）切換或上下排列，自己判斷哪個對老師比較直覺：

**學生名冊**
- 「貼上名冊」：一個大文字框，提示「從 Excel 複製『座號』和『姓名』兩欄貼上」
  - 支援 Tab、逗號、空白分隔；容忍空行、前後空白、全形數字
  - 按「預覽」後顯示解析結果表格，有問題的列標紅並說明原因（座號重複、缺姓名…）
  - 確認後「加入名冊」；若座號已存在，詢問要「更新姓名」還是「略過」
- 名冊表格：座號、姓名、修改、刪除
- 單筆新增學生

**分組**
- 分組列表（每套分組的名稱、組數）
- 「新增分組」→ 選方式：
  - 隨機分組：輸入「分成幾組」或「每組幾人」（二選一），人數盡量平均（各組人數差最多 1）
  - 手動分組：先輸入組數，所有學生在「未分組」區
- 分組編輯畫面：
  - 每組一個區塊，顯示組名和成員（座號 + 姓名）
  - 點組名可改名
  - 點一位學生 → 跳出選單選「移到第 X 組」或「移出分組」。**不要用拖曳當唯一操作方式**
  - 「重新隨機」（確認後重排）、「複製這套分組」、「刪除」
- 「投影顯示」：全螢幕、大字、高對比列出各組成員，按 Esc 或「關閉」離開

**班級設定**
- 改班名、重新產生加入碼（提示：已發給學生的舊碼會失效）、刪除班級（要輸入班名確認）

## 網址與重新整理

目前 Cloudflare 的 SPA fallback 會把找不到的路徑（例如 `/t/class/123`）回傳**學生端**的 `index.html`，所以老師端子頁面重新整理會變成學生畫面。

老師端子頁面請用 hash 路由（例如 `/t/#/class/<id>`），不需要改 Worker 設定。要求：在任何老師頁面按 F5 都留在原畫面；瀏覽器「上一頁」能正常回到上一個畫面。不要引入 router 套件，自己用 `hashchange` 處理即可。

## API

RESTful、JSON 即可，全部需要老師登入。資料驗證放在後端（長度上限、必填、座號為正整數…），錯誤訊息用中文回給前端顯示。

## 驗收

- `pnpm typecheck`、`pnpm test`、`pnpm build` 通過
- 新 API 要有測試確認未登入回 401（可沿用 `auth.test.ts` 的寫法）。D1 相關測試優先用 `@cloudflare/vitest-pool-workers`；若和目前的 Vitest 版本不相容，改把資料驗證和分組邏輯抽成純函式來測。不要安裝需要編譯的原生套件（例如 better-sqlite3，Windows 上容易裝失敗）
- 測試至少涵蓋：名冊解析（各種分隔、全形、空行、重複座號）、隨機分組人數平均、同套分組學生不會出現在兩組、刪除班級連帶刪除
- PR 描述附上 build 大小
- PR 描述用老師的角度寫一段「操作流程」：從建立班級到投影分組，每一步點什麼。如果寫起來很繞，代表介面要改
- 若環境有 Playwright 或其他方式可以截圖，附上主要畫面截圖（手機寬度與桌機寬度各一）

## 不要做

- 學生端任何功能、學生自選組
- 拖曳排序、動畫
- 匯入 Excel 檔案（只做貼上）
- 部署（使用者 merge 後會自己決定）
