# Phase 5：簡答題上課互評

先讀 `CLAUDE.md`、`docs/PRODUCT.md`、`status.md`。Phase 4 已合併並部署，老師試用沒有問題。

## 目標

上課時，簡答題停止作答後，老師可以讓學生**隨機互評**：每位有作答的學生匿名看到另一位同學的答案，給 1～5 分和一句評語。互評結束後，每位學生看到自己收到的評語。互評結果**只給老師參考，不算進成績**。

這是第一版，先只做「隨機、一人評一人、匿名」。自選、分組互評之後看效果再決定，**不要預先做設定項**。

## 上課流程（簡答題）

題目狀態多一個「互評中」：

```
未出題 → 作答中 → 已停止 → 互評中 → 已公布
                      └──（跳過互評）──→ 已公布
```

1. 簡答題「停止作答」後，老師畫面的主要按鈕是「**開始互評**」，旁邊一個次要按鈕「跳過互評，直接公布」
2. 按下「開始互評」時，伺服器在**有交答案的學生**之間隨機分配：把他們洗牌排成一圈，每人評下一位。這樣每人剛好評 1 份、被評 1 份，也不會評到自己
   - 交答案的人少於 2 人時，「開始互評」停用，並說明「至少要 2 位同學作答才能互評」
   - 分配在開始時就固定，之後有人加入或解除綁定也不重新分配
3. **互評中**的老師畫面（會投影）：大字「互評中，已完成 N／M 人」，主要按鈕「結束互評」。還有人沒評完時按下，要確認「還有 X 人沒評完，結束後就不能再評」
4. 按「結束互評」後，題目變成「已公布」，學生看到自己收到的評語
5. 互評中直接按「出下一題」也可以：跟「結束互評」一樣，先問同一個確認，再把這題設為已公布、出下一題

老師在互評中可以按次要按鈕「看評語」，列出「評分者 → 被評者、分數、評語」，每則有「刪除」（用在不恰當的評語；刪除後被評者會看到「這次沒有收到互評」）。按下「看評語」前提醒「投影中會被學生看到」。

## 學生端

- **互評中，有作答的學生**：
  - 標題「請評這位同學的答案」，**不顯示對方姓名和座號**
  - 對方的答案（字要大，可捲動）
  - 「給幾分？」1～5 五個大按鈕（整列，至少 48px）
  - 「評語」多行輸入框，**必填**，1～200 字，下方顯示剩餘字數
  - 主要按鈕「送出評語」。送出後顯示「已送出，在老師結束互評前可以修改」，可以修改再送出
- **互評中，沒作答的學生**：顯示「這題你沒有作答，這次不用互評，等老師下一步」
- **已公布（有互評過的簡答題）**：顯示「你收到的互評」：分數（例如「4 分（滿分 5 分）」）和評語，**不顯示評分者**。沒收到（對方沒評或被老師刪除）時顯示「這次沒有收到互評」。下方照舊顯示「老師之後批改」或已批改的分數
- 斷線重連、重新整理後，要回到正確的互評畫面，已輸入但還沒送出的評語不用保留
- 下課結果清單（Phase 3.5）：簡答題的結果欄位不變，不需要顯示互評

## 資料

新 migration，自行設計，需涵蓋：
- 互評分配：上課題目、評分者、被評者、分數（1～5，未評為 NULL）、評語、送出時間
- 同一題中，一位學生最多評 1 份、最多被評 1 份（用 unique 限制）
- 刪除上課紀錄、刪除學生時連帶刪除（cascade）
- 題目狀態加 `reviewing`；相關型別（`QuestionStatus`、狀態轉換表）跟著改

## 安全要求（重點測試）

- 評分者拿到的只有**被評者的答案文字**：API 回應裡不能有被評者的 id、座號、姓名
- 被評者看到的評語裡不能有評分者的任何身分資訊
- 只能在「互評中」送出評語，而且只能評分配給自己的那一份
- 分數必須是 1～5 的整數，評語去掉前後空白後 1～200 字
- 沒被分配的學生（沒作答的、後來才加入的）送出評語會被拒絕
- 互評相關的老師 API 未登入回 401

## 上課紀錄與 Excel（Phase 4 的頁面）

- 簡答題的題目詳情：每位學生除了作答內容，再顯示「收到的互評：4 分・評語」和「他評了誰：5 號・3 分・評語」
- **簡答批改畫面**：在學生作答下方，用淡色小字顯示他收到的互評（分數＋評語），標示「同學互評，僅供參考」，方便老師批改時參考
- 每題統計：互評過的簡答題多顯示「互評平均 3.8 分」
- 單堂 Excel 多一張工作表 `互評`：題號、被評者座號、被評者姓名、評分者座號、評分者姓名、分數、評語。這堂課沒有互評時不產生這張表
- **互評分數不加進任何總分、得分率、平均分數**

## 驗收

- `pnpm typecheck`、`pnpm test`、`pnpm build` 通過
- 測試至少涵蓋：分配結果每人剛好評 1 份、被評 1 份、不評自己（用 2、3、30 人各測一次）；少於 2 人不能開始；上面「安全要求」每一條；結束互評後不能再送；刪除評語；出下一題會結束互評；刪除上課紀錄連帶刪除互評；互評分數不影響 `analyze()` 算出的總分
- 手動測試：本機 1 個老師分頁 + 4 個學生視窗（其中 1 人不作答），跑一次互評流程，途中重新整理一個學生視窗
- PR 附截圖：老師互評中畫面、學生評分畫面（手機）、學生收到互評畫面（手機）、批改畫面顯示互評參考
- PR 描述用老師和學生的角度各寫一段流程
- 更新 `docs/PRODUCT.md` 的「同儕互評」一節，改成這次實際做的內容（隨機、一人評一人、匿名、1～5 分＋評語、只供參考）

## 不要做

- 自選互評對象、分組互評、一人評多份、互評設定項
- 評分者實名
- 學生端看到其他人的評語或互評排名
- 互評分數算進成績
- 部署（使用者 merge 後自己決定）
