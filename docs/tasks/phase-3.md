# Phase 3：上課（加入、推題、即時作答、公布答案）

先讀 `CLAUDE.md`、`docs/PRODUCT.md`（特別是「典型的一堂課」和「學生身分」）、`status.md`。Phase 2 已合併到 main。

這是整個工具最核心、也最容易在真實網路下出問題的部分。**寧可簡單、穩定，不要花俏。**

## 目標

老師選班級和題組開始上課，學生用手機加入、作答，老師即時看到作答人數，停止作答後公布答案，學生看到自己對錯。下課後資料留在 D1，Phase 4 再做統計頁面。

## 架構（請照這個做）

**所有資料都走一般的 HTTP API + D1；WebSocket 只負責「通知有東西變了」。**

- Durable Object `LessonHub`：每堂課一個（用 lesson id 取得）。它只做一件事：維持老師和學生的 WebSocket 連線，收到 Worker 的通知後廣播給大家。**不存任何狀態、不碰 D1。**使用 Hibernation API（`ctx.acceptWebSocket`、`webSocketMessage`、`webSocketClose`），用 tag 區分 `teacher`／`student`
- 廣播的訊息只有事件名稱，**不含任何資料**，例如 `{"t":"question"}`（題目狀態變了）、`{"t":"answers"}`（有人交答案，只發給老師）、`{"t":"roster"}`（有人加入或解除綁定，只發給老師）、`{"t":"ended"}`
- 前端收到通知後，用 HTTP API 重新抓目前狀態。斷線重連、手機從背景回來（`visibilitychange`）時，也一律重抓一次
- 因為 WebSocket 不傳資料，連線本身不需要驗證身分，網址帶 lesson id 就好
- 所有會改變狀態的 API（開題、交答案…）在寫完 D1 後，呼叫 DO 廣播。廣播失敗不能讓 API 失敗（`catch` 後記 log 即可），前端靠重連重抓補上
- WebSocket 斷線後自動重連：1、2、4、8 秒，之後每 10 秒一次；畫面角落小字顯示「連線中斷，重新連線中…」，不要跳出對話框
- 測試時把 DO 的廣播換成假的（記錄呼叫了什麼），只測 HTTP 與 D1 邏輯。DO 本身保持在 50 行左右，用手動測試驗證

## 資料表（新 migration）

自行設計，需涵蓋：
- **上課**：班級、使用的題組（名稱也存一份）、狀態（進行中／已結束）、開始與結束時間。**同一時間只能有一堂進行中**
- **上課的題目**：開始上課時把題組的所有題目**整份複製**進來（題型、文字、提示、配分、答案設定、順序）。之後修改或刪除題組都不影響這堂課。每題有狀態：未出題／作答中／已停止／已公布
- **作答**：上課題目、學生、作答內容、評分結果、送出時間。同一學生同一題只有一筆；作答中可以改答案，以最後一次為準
- **學生裝置綁定**：學生表加一個欄位存裝置 token 的 SHA-256。綁定是**跨堂課**的，下次上課同一支手機會自動認得
- 刪除班級要連帶刪除上課紀錄與作答

## 學生端（`/`）

1. **輸入加入碼**：6 位數字。打錯顯示「找不到這個加入碼，請再確認一次」；班級沒有進行中的課顯示「老師還沒開始上課，請稍等」，並每 10 秒自動重試（這裡可以用 polling，因為還沒加入任何一堂課）
2. **選座號**：列出名冊（座號＋姓名，大按鈕，一行一個）。已被別支手機綁定的座號顯示為灰色「已有人使用」，點了提示「請找老師」
3. 點選後產生隨機 token 存在 `localStorage`，送到伺服器綁定。之後重新整理、斷線、隔天上課都自動回到正確畫面。`localStorage` 不能用時（無痕模式等），退回 `sessionStorage` 並提示「請不要關閉這個分頁」
4. **等待畫面**：大字「{座號} {姓名}，已加入」＋「等老師出題」。顯示「不是我？」連結：解除這支手機的綁定、回到選座號
5. **作答**：用 Phase 2 的 `QuestionView` 顯示題目，下方大按鈕「送出答案」。送出後顯示「已送出，可以在老師停止前修改」，答案仍可改、可再送出
6. **停止作答**：顯示「老師已停止作答」，鎖住
7. **公布答案**：顯示自己對或錯（大字、顏色＋文字，不能只靠顏色）、正確答案；填空題顯示每格對錯。簡答顯示「老師之後批改」
8. **下課**：「這堂課結束了，謝謝！」

## 老師端（`/t/`）

### 開始上課
- 班級頁和首頁都有「開始上課」主要按鈕 → 選題組 → 「開始」
- 已有一堂進行中的課時，首頁最上方顯示醒目的「上課中：{班級}，回到課堂」；要開新課，先問是否結束舊的

### 上課畫面（會投影，字要大）
- **等待加入**：超大加入碼、學生要打開的網址（顯示完整網址，字要大）、QR code（可選，見下方）、「已加入 N／M 人」、已加入的座號格子（未加入的淡色）
- **出題**：顯示題目列表（題號＋前 20 字），目前題目醒目。主要按鈕依狀態變化：「出這一題」→「停止作答」→「公布答案」→「下一題」。最後一題公布後，主要按鈕變成「結束上課」
- **作答中**：大字顯示題目和「已作答 N／M 人」。**作答中不顯示答案分布**（投影出來會影響還沒作答的學生）
- **停止作答後**：顯示答案分布（選擇題各選項人數長條；是非題 ○／✕ 人數；填空題每格正確率；簡答只顯示人數）。正確答案先不標出
- **公布答案後**：標出正確答案、正確率
- **簡答題**：停止後可以按「看作答內容」，列出座號、姓名、內容。按下前提醒「投影中會被學生看到」
- 「名單」按鈕：已加入的學生、每人這題是否已交。每位學生旁有「解除綁定」（確認：「解除後，這位學生要重新選座號，換手機或點錯人時使用」）
- 「結束上課」：確認「結束後學生就不能再作答」
- 老師關掉分頁再打開，要回到同一堂課的同一個狀態

### QR code（可選）
如果加一個小的 QR 產生套件（gzip 後 15 KB 以內、無其他依賴），可以在等待畫面顯示學生網址的 QR code，學生用相機掃描就能打開。請在 PR 說明選了哪個套件、多大。找不到合適的就先不做。

## 安全要求（重點測試）

- 題目在「已公布」之前，學生 API 只能回傳 `toStudentView` 的結果；公布後才回傳該生自己的評分結果與正確答案
- 學生 API 以 token 找出學生；token 只能操作自己、而且只能在自己班級進行中的課
- 只有「作答中」的題目可以交答案；交答案時由伺服器用 `gradeAnswer` 評分，不相信前端
- 學生拿不到別人的作答內容與成績
- 同一座號已被綁定時，別的 token 不能再綁

## 驗收

- `pnpm typecheck`、`pnpm test`、`pnpm build` 通過
- 測試至少涵蓋：上課題目是複製的（改題組不影響）、公布前學生拿不到答案、停止後不能交、作答中重交會覆蓋、token 不能冒用別人、座號重複綁定被擋、解除綁定、一次只能有一堂進行中、刪除班級連帶刪除上課紀錄
- 手動測試：本機開一個老師分頁和至少 3 個學生視窗（用不同的瀏覽器或無痕視窗，各自有獨立的 `localStorage`），跑完一堂 5 題的課（五種題型各一）。途中把一個學生分頁重新整理、把老師分頁關掉再打開，確認都回到正確狀態
- PR 描述：build 大小、老師角度的上課流程、學生角度的流程、截圖（老師等待加入畫面、老師作答中畫面、學生作答畫面、學生公布答案畫面）
- PR 描述最後寫一段「**用真手機測試的步驟**」給使用者：部署後怎麼用家裡幾支手機（含行動網路和 Wi-Fi）模擬一堂課，要特別觀察哪些地方（例如手機螢幕關掉再打開、切換 App 再回來）

## 不要做

- 統計頁、上課紀錄列表、Excel 匯出（Phase 4）
- 互評、分組相關功能（Phase 5）
- 老師手動批改簡答
- 倒數計時、排行榜、音效、動畫
- 學生端顯示其他人的作答或排名
- 部署（使用者 merge 後自己決定）
